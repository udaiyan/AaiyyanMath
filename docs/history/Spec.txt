# PROJECT SPECIFICATION
# Native Rust Engineering Mathematics and Computational Environment

Version: 2.0

## 1. PROJECT VISION

Develop a professional desktop engineering mathematics and computational environment called AaiyyanMath, combining the most useful features of:

- PTC Mathcad
- MATLAB
- Wolfram Mathematica
- Python scientific computing

The application must be written primarily in Rust.

It must provide a mathematical worksheet interface where users can enter natural mathematical equations, define variables, perform engineering calculations, solve differential equations, manipulate matrices, create graphs, conduct numerical simulations and generate professional engineering reports.

Python must be embedded into the application using PyO3.

Python is the computational scripting backend, not the primary user interface or mathematical language.

The application must automatically translate mathematical worksheet expressions into equivalent Python code using NumPy, SciPy, SymPy and other scientific libraries.

The mathematical worksheet is the primary interface.

The generated Python code must be available for inspection, editing, execution and export.

The product must support Windows, Linux and macOS.

## 2. CONFIRMED ARCHITECTURAL DECISIONS

### Units

Use a hybrid unit architecture:

- Python Pint interoperability.
- Consistent unit representation between the worksheet and Python backend.

## 7. PYTHON CODE GENERATION

    b := 10
    c := sqrt(a^2 + b^2)

    a = 5
    b = 10
    c = math.sqrt(a**2 + b**2)

Automatically select suitable libraries.

Use:

- NumPy for numerical arrays.
- SciPy for numerical methods.
- SymPy for symbolic calculations.

## 8. EMBEDDED PYTHON RUNTIME

Use PyO3 to embed Python into the Rust application.

Do not launch a separate Python process as the primary execution architecture.

Create a dedicated Python execution worker thread.

Responsibilities:

- Initialise and manage Python execution.
- Execute generated scripts.
- Execute imported Python functions.
- Exchange data with Rust.
- Return results.
- Handle exceptions.
- Capture output.
- Manage cancellation where supported.
- Prevent GUI blocking.

Use Rust channels or an equivalent message-passing system between the GUI and execution worker.

Respect the Python Global Interpreter Lock.

Do not hold the GUI thread while waiting for Python calculations.

Initialise the Python interpreter once and establish a controlled lifecycle.

### Python packaging

Support bundled or managed Python runtimes.

Provide dependency management for Windows, Linux and macOS.

Document Python version compatibility.

Ensure required numerical libraries are available after installation.

Avoid requiring users to manually configure Python installations.

### Python execution security

Clearly distinguish generated application code from user-authored Python.

Imported Python scripts must be treated as potentially unsafe.

Provide explicit user trust controls.

Do not claim that embedded Python provides process isolation or sandboxing.

Design the runtime interface so an isolated execution backend could be added in the future.
