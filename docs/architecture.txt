AAIYYANMATH ARCHITECTURE (implementation notes, spec v2.0)

Crate layering (no cycles):

  ast            authoritative expression/statement tree, LaTeX + math text
  units          dimension algebra, unit registry, quantities, unit parsing
  parser         lexer + Pratt parser -> AST (no regex)
  evaluator      native values, environment scopes, builtins, linear algebra
  dependency     definition graph, topological order, cycles, invalidation
  codegen        AST -> Python (library selection, scalar vs array, Pint units)
  python_runtime PyO3 worker thread, JSON protocol, cancellation, trust flags
  symbolic       SymPy bridge (scripts + result collection)
  plotting       plot specs, native sampling, offline SVG
  worksheet      blocks, document model, undo/redo
  project        versioned JSON, settings, metadata, atomic save + backup
  reporting      Typst / HTML / Markdown / Python export, optional PDF
  core           session orchestration, schedulers, results, exports
  gui            egui panels, native math typesetting, 2D/3D rendering, editor
  app            eframe entry point, CLI, autosave

Threading model:
  GUI thread     egui only; never evaluates mathematics, never touches the GIL
  native worker  evaluates AST jobs, honours cancel flag + deadline
  python worker  owns the interpreter; GIL held only during a request

Data interchange:
  Quantity = { si base value, unit descriptor (name, dimension, factor, offset) }
  Python reports values through aaiyyan_runtime.report(); the payload is JSON
  and is mapped back into native Values by core::convert.

Recalculation:
  parse blocks -> build graph -> detect cycles -> pick full or incremental set
  -> generate Python (always, for inspection) -> native job -> optional Python
  job -> overlay results. Controls rewrite their assignment before evaluation.
