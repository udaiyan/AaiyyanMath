AaiyyanMath - known limitations
Updated to match the MATLAB-parity function catalog and the grid canvas.

LANGUAGE / SYNTAX
 1. Element-wise operators .*, ./, .^ and .\ are NOT implemented. *, / and ^
    are matrix/scalar operators only (MATLAB parity gap, planned tranche 2).
 2. Indexing is partial: A(i,j) and A(i, j) work; the colon range works via
    colon(a,b,c) and a:b:c in definitions, but the `end` keyword inside
    indices, logical indexing A(A>9) and single linear index A(8) are not
    parsed yet.
 3. No statement-level for / while / if-elseif blocks. Conditionals are
    expression form only: `if c then a else b` and `if(c, a, b)`.
 4. Text is a scalar string value; there is no char-vs-string distinction and
    no string arrays.

ENGINE / NUMERICS
 5. Native values are double-precision reals, complex scalars and 2-D
    matrices. No single/int8..uint64 classes, no sparse storage, no N-D
    arrays (page-wise functions route to Python).
 6. The following require the embedded Python backend; in a native-only build
    they raise a clear "routed to embedded Python" error on the region:
    fft, ifft, fft2, conv2, filter, pwelch, periodogram, roots, logm, sqrtm,
    lu, qr, chol, svd, eig, eigs, svds, cond, sylvester, lyap, the page-wise
    family, pcg/bicg/bicgstab/cgs/gmres/minres/qmr/symmlq/tfqmr/lsqr/lsmr,
    ode45/ode23/ode113/ode15s/ode23s/ode23t/ode23tb/decic, bvp4c/bvp5c/
    bvpinit/deval, dde23/ddesd/ddensd, pdepe, interp2/interp3/interpn/
    griddedInterpolant/scatteredInterpolant/spline/pchip/csaps, delaunay/
    delaunayn/tsearchn/dsearchn/convhull, fminbnd/fminsearch/fmincon/fsolve/
    fzero/lsqnonlin/lsqcurvefit/fitlm, and the named-distribution samplers.
 7. magic(n): odd and doubly-even orders match MATLAB exactly; singly-even
    orders (6, 10, 14, ...) are valid magic squares via Strachey but the
    column ordering can differ from MATLAB's output.
 8. expm uses scaling-and-squaring with a Taylor series rather than a Pade
    approximant; accurate for moderate norms, less so than MATLAB's algorithm
    for very large norms.
 9. Editing any region source forces a full re-evaluation of the worksheet.
    Correct, but not yet a minimal incremental recompute.
10. Native rng(seed) uses an xorshift64* stream. Generator names such as
    "twister" are accepted but the stream is not bit-identical to MATLAB's
    Mersenne Twister; the Python backend uses NumPy generators.

GUI
11. Undo/redo covers worksheet edits. Panel sizes, zoom, pan and palette
    state are session-only and are not persisted in the project file.
12. 2-D plots support zoom/drag; image export (PNG/SVG) goes through the
    Python backend only.
13. There is no live-script (.mlx) equivalent; projects are JSON files
    (*.aaiyyan.json) with a recovery snapshot in the temp directory.

INTEROP
14. Generated Python is a derived artefact: it is runnable and inspectable,
    but editing it does not feed back into the worksheet.
15. No .mat import/export. Tabular input is CSV via read_csv.

CI
16. The workflow matrix covers ubuntu-latest and windows-latest only; there
    is no macOS runner and no release-artefact build yet. The lint job
    (rustfmt + clippy -D warnings) is advisory until the tree is warning-free.
