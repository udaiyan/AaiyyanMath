TECHNICAL RISKS AND MITIGATIONS

PyO3 / interpreter availability
  Risk: build fails or app cannot start without a matching libpython.
  Mitigation: `python` is a non-default cargo feature; the native engine is a
  complete fallback and the UI reports runtime status honestly.

GIL and UI responsiveness
  Risk: GUI stalls during long calculations.
  Mitigation: two worker threads (native + Python), message passing, no GIL on
  the GUI thread, deadlines and cooperative cancellation.

egui API churn
  Risk: minor egui releases change App/creator signatures.
  Mitigation: exact pins (=0.28.1); upgrade notes in docs/python.txt.

Unit correctness across the boundary
  Risk: silent unit loss when values cross into Python.
  Mitigation: canonical SI value + unit descriptor, Pint mirroring, dimensional
  checks in the native engine, round-trip tests.

Type inference for '*' vs '@'
  Risk: wrong operator in generated Python for mixed expressions.
  Mitigation: two-pass ordered inference; the original mathematics is emitted
  as a comment above every generated statement.

Security expectations
  Risk: users assume embedded Python is isolated.
  Mitigation: explicit trust flags, warnings in the UI, no sandbox claims, and
  a protocol designed for a future isolated backend.
